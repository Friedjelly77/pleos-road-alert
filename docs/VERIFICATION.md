# 검증 기록

2026-11-07, Windows에서 Python 서버와 Android APK를 실행했다. Android Studio로 기동한 Pixel 3a API 35, 실제 설치한 앱, PC의 별도 참여자 프로세스가 `adb reverse`로 연결됐다. 관측에 사용한 위치는 모두 가상 도로다.

| 시나리오 | 실행 위치와 결과 |
|---|---|
| 앱 A 등록 → 접근 중인 B | APK의 **사고 제보**를 눌러 접수 표시를 확인했다. PC 참여자가 같은 사건 ID를 수신했다. |
| PC A 등록 → 앱 B | 별도 참여자가 1,000 m 지점에서 등록했다. 400 m 지점의 APK가 전방 약 600 m 경고를 그리고 상세 버튼을 표시했다. |
| 반대 방향·통과·교차로·고가·하부 | 서버 테스트에서 각각 수신 0건. 역방향 도로의 정상 접근 차량은 1건. 위치 오차 범위가 겹치는 경우와 범위 밖 차량도 제외했다. |
| 오래된 위치·낮은 정확도 | 서버 테스트에서 오래된 수신자 위치와 정확도 36 m 조건은 경고 0건. 오래된 발생 위치를 담은 신규 접수도 거절했다. |
| 중복·묶기 | 같은 제보를 16개 동시 호출해 사건 1건. 충돌하는 요청 ID는 거절했다. 다른 참여자의 근접 제보는 같은 사건을 보강했고 발생 위치·시각을 보존했다. |
| 해소·취소·만료 | 해소 후 실제 APK 경고가 사라졌다. APK에서 올린 제보의 취소 응답을 화면에서 확인했다. 시간 제어 테스트로 정확한 만료 경계, 만료 후 재전송·보관 기간 경과 삭제를 확인했다. |
| 끊김·재접속 | APK의 ADB 포트 연결을 제거한 뒤 제보했다. 대기 표시와 미접수를 확인하고 연결 복구 후 단일 접수를 확인했다. 별도 HTTP 테스트에서는 서버 자체를 재시작한 뒤 SQLite의 접수 기록으로 재전송을 처리했다. |
| 급감속·비상등 | Kotlin 테스트에서 두 입력은 확인 요청만 생성했다. 브레이크 단독·정지 유지·순서가 뒤바뀐 속도 샘플은 사고로 올라가지 않았다. 서버도 약한 신호의 자동 사고 등록을 거절했다. |
| 실제 SDK와 가상 입력 분리 | 실제 Vehicle AAR를 사용한 컴파일, 가상 모델의 전개 변화·출처 분리 테스트 통과. SDK 모드에서도 가상 도로를 선택하면 사건에는 데모 표시가 붙는다. 양산차 및 Pleos 서비스 콜백 실측은 미확인. |
| Android 위치 SDK | 일반 에뮬레이터의 GNSS 좌표 주입 → Android LocationManager 콜백 → 앱 화면에 정확도·방향·측정 경과 표시를 확인했다. 도로 매칭이 없는 실제 도로 모드에선 공유를 보류했다. 시험 후 위치 권한을 회수했다. |

### 지연 관측

다섯 시각과 동일 호스트 시계의 측정값을 [수신 추적 JSON](trace.json)에 남겼다. `createdAt`과 `sentAt`은 제보 클라이언트, `serverReceivedAt`은 서버 접수, `clientReceivedAt`과 `viewDrawnAt`은 APK 수신과 경고 화면의 실제 View 그리기 콜백 시각이다. 마지막 값은 패널이 빛을 낸 시각과 구분된다.

**PC가 사건 생성을 시작한 시점부터 APK 그리기 로그가 같은 PC에 돌아온 시점까지** 세 회차에서 각각 **94 ms, 110 ms, 156 ms**가 걸렸다. 이 값에는 로그 전달 시간도 포함된다. 가로 레이아웃 개선 후 다시 설치한 최종 APK 회차(156 ms)에서 APK 수신→그리기는 16 ms였다. 호스트와 에뮬레이터 벽시계가 약 2.8초 어긋나므로 둘의 타임스탬프를 직접 빼서 편도 지연을 계산할 수 없다. 이 측정은 로컬 가상 도로 시연에 한정된다.

### 재현과 증거

| 작업 | 결과 |
|---|---|
| Gradle `:app:assembleDebug :app:testDebugUnitTest` | 빌드 성공, Kotlin JUnit 3개 통과 |
| Python `unittest discover -s tests -v` | 9개 통과. 실제 HTTP 롱폴링·서버 재시작 및 규칙 테스트 포함 |
| APK 서명 및 설치 | Android Build Tools의 apksigner v2 확인. API 35에 adb install 성공 |
| `tools/device_check.py` | 설치된 앱의 버튼을 조작해 양방향 전송, 화면 그리기, 해소, 연결 복구, 취소 확인 |

에뮬레이터 화면은 [가로 수신 화면](approach.png)과 [세로 수신 화면](approach-portrait.png), 실행 결과는 [테스트 실행 기록](run.txt)에서 확인할 수 있다. `ROAD_PORT`나 TTL을 바꿨을 때의 테스트는 별도 서버 DB에서 진행한다.

### 다음 개발 우선순위

1. **Pleos 런타임에서 첫 차량 신호 확보.** 전용 이미지를 받았지만 셸의 `WHvGetCapability`가 `0x80070005`로 거부됐다. 소프트웨어 기동도 ADB offline에 머물러 종료했다. Studio용 전역 AVD 포인터 쓰기도 차단됐다. 작업 폴더의 실행기로 부팅한 뒤 실제 서비스 버전·권한·좌석별 capability를 기록하고, 콘솔의 브레이크 페달 변화를 앱의 제보 선택 강조와 대조한다. 전개 이벤트는 공식 주입 수단 확인이 다음 단계다.
2. **실제 도로 데이터 연결.** 신뢰할 수 있는 도로 구간·방향·층위를 판정하는 공급자를 선택한다. 현재 모델은 같은 가상 구간 안에서만 동작한다. 연결된 다음 구간, 갈림길, 실도로 상하부, 차선은 판정할 수 없다.
3. **배포 정책·보안.** 주행 허용 카테고리와 오디오 우선순위를 확인하고 전용 기기 두 대로 반복 시험한다. 상용 서버에는 HTTPS, 참여자 인증·속도 제한, 악성 제보 및 허위 다중 확인 방지, 위치 처리·삭제 정책이 필요하다. 로컬 자격증명은 설치 단위여서 재설치한 동일 인물을 구분할 수 없다.
4. **현장 검증.** 시계 동기화와 끊김·권한 철회·프로세스 종료를 포함한 반복 측정, 사용자 입력 부담과 오경보율 검증을 진행한다. 상용 교통 데이터·정밀 차선 정보·자동차 제어·119 연결은 이번 시연 범위 밖이다.
